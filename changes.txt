================================================================================
1. SUMMARY
================================================================================

The tag box listed every Trip/Event ever created, so finished trips cluttered
it more every year. Now every way of tagging a transaction (the inline tag
box, the split modal and the bulk "Set Trip/Event..." dropdown) lists only
CURRENT trips by default. A "See past tags (N)" button at the bottom of the
box reveals the rest, greyed out with their status beside them.

A fourth status, "Completed Investment", separates investments that have
ended from ones that are still running ("Investment").

  CURRENT status = "Active" | "Investment"
  PAST status    = "Completed" | "Completed Investment"
  A missing or unrecognised status counts as "Active", so a typo in the
  sheet can never hide a tag someone needs.

ACTION NEEDED: paste google-apps-script/Service_Tags.gs into Apps Script and
deploy a NEW VERSION of the web app BEFORE (or together with) the frontend.
An old backend rejects "Completed Investment" with "Invalid status". Nothing
is corrupted (the existing save-failure path reports it), but the status
does not save.

core/trip-status.js (NEW, pure: no DOM, no store)
  - TRIP_STATUS: { ACTIVE, COMPLETED, INVESTMENT, COMPLETED_INVESTMENT }
  - TRIP_STATUSES (display order) and PAST_TRIP_STATUSES.
  - TRIP_STATUS_STYLES: { icon, color, label } per status. Replaces the
    five copies of the same map that were in tags.list.js and
    tags.sublist.js. The new status is 🏦 in gold (#c9a227); all four icons
    differ, for accessibility mode.
  - NEXT_TRIP_STATUS: click-to-cycle order on the Tags page,
    Active -> Completed -> Investment -> Completed Investment -> Active.
  - normaliseTripStatus(status): known status -> itself; missing or
    unknown -> "Active".
  - isPastTripStatus(status): true only for Completed and Completed
    Investment.
  - getTripStatusStyle(status), getNextTripStatus(status): both normalise
    first, so an unknown status displays and cycles as Active.
  - partitionTripsByStatus(trips, tripStatusMap) -> { current, past }:
    keeps input order and drops non-strings (the same guard the
    TagSelector already used).

shared/tag-selector.component.js
  - show() gains an optional last argument, { pastOptions = [] }, a list of
    { value, hint } items. Every existing call keeps working unchanged
    (the Tags-page Type selector is one of them).
  - this.showPast is view state for the open box only. It resets to false
    in show() and close(), so it does not belong in the Store.
  - renderList(): lists current options, plus past options when showPast is
    on, filtered by search and sorted together as before. Past items get
    the class "tag-selector-item--past" and a status hint. onSelect still
    receives the plain string value.
  - When the search matches no current tags but does match hidden past
    ones, the empty state reads "No current tags match — N past tags do".
  - A real <button type="button"> at the foot of the box reads
    "See past tags (N)" / "Hide past tags" (with aria-expanded). It is
    built once, so it keeps keyboard focus when the list re-renders, and it
    only shows when there are past options. Clicking it re-renders the list
    and calls updatePosition(), because the taller box may need to flip
    upwards. Tab reaches it; Enter and Space work by default; Escape still
    closes the box.
  - The selector does not know what a status is: the caller builds both
    lists.

shared/tag-selector.css
  - .tag-selector-item--past (muted text), .tag-selector-item-label,
    .tag-selector-item-hint (small italic right-aligned status) and
